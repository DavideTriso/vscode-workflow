# Implementation run: skills always start their subagent

## Summary

Logic Review, Code Readability, Document and Code Comments now each have a subagent that holds the criteria and launcher skills that start it, so reports are written every time. Typecheck and all 112 tests pass. Live runs of the launchers and the version bump are still open.

## Full Record

### User request

Go with option A from the saved plan (`implementation-plan.md`, status Selected) and apply it to Document and Code Comments as well.

### Implementation summary

- Agents (`logic-review`, `code-readability`, `document`, `code-comments`) now contain their own criteria and rules. The `Skill` tool is removed from their `tools`, so they no longer load a skill.
- `logic-review-default`, `code-readability-default`, `documentation-update-default`, `code-comment-review` and `code-comment-improve` are launcher skills. Each one's first action is an `Agent` call with the matching `subagent_type`, with the request, intent, scope (and mode) in the brief.
- Code Readability launcher: after the agent returns, asks which proposals to apply, applies only those, and re-syncs the TODO list with `sync_code_readability_todos`.
- Document launcher: passes the absolute path of `documentation-standards.md` (built from its own base directory) in the brief; the agent reads the standards from that path and stops if it is missing. When the agent returns `Status: Awaiting Confirmation`, the launcher shows the question and runs the agent again with the answer.
- Code Comments keeps its no-report contract; the launchers add isolation only.
- `documentation-create-default` and both `documentation-standards.md` copies are unchanged.
- Quick Reference text and the docs describe the new behavior.
